One thing to open, to see the whole platform

no more hunting for the right file

Until recently, every part of this project lived in its own separate technical project, which meant knowing which one of several files to open just to see something running. There is now a single entry point that opens the whole platform at once — the actual clickable website, plus a short guided walkthrough for each underlying piece: the claim/voting engine, the currency ledger, the reputation scoring, the marketplace, and the governance/roles layer. This didn't change what any of those pieces do; it just means a visitor, or anyone picking this project up cold, no longer needs to be told where to look first.

A change of direction

what moved, and why

This project started as a recycling-specific idea: submit proof you recycled something, get it approved, earn a token. On 2026-08-29, at your direction, the scope broadened. The recycling framing turned out to be one example of a more general, more useful idea: a "digital parliament" — a platform where a community writes structured entries (claims, proposals, rules), discusses them, and votes on them, with mechanics layered on top of ordinary voting/forum software to keep the community's shared record honest and self-consistent. The recycling-specific pieces — the reward token, the submit/approve/earn flow — are now historical: still built, still tested, but not what this project is actively extending. Everything below describes what the project actually is today.

This remains, in every respect, a proof of concept on a free public test network — no real money, no real tokens with market value, nothing an investor or end user can use yet.

What it is, in plain terms

a community record that keeps itself honest

Picture a community wiki where every entry is a claim — "we should adopt rule X," "this fact is true," "this proposal is approved" — that people can vote on. A handful of things make it more than an ordinary wiki-plus-voting.

Claims remember what they depend on

If claim B was only written because claim A was accepted, and the community later votes claim A back down, B doesn't just sit there quietly looking as valid as ever — it automatically flips to "under review," along with anything that depended on B, and anything that depended on that, no matter how many steps removed. Nothing has to notice this by hand; the system walks the whole chain of dependencies for you. Think of it like a family tree: knock out an ancestor, and every descendant is flagged, not just the direct child.

Contradictions get flagged automatically

Claims can be marked as conflicting with each other. If two claims that currently both stand as "accepted" turn out to directly contradict one another, the system surfaces that instead of letting the community's shared record quietly hold two incompatible truths at once.

A currencyless ledger

Instead of one shared token everyone earns, each community member can mint, trade, and redeem (burn) their own personal currency. Whether anyone else accepts your currency is entirely a trust decision the community makes, based on your public track record — not something the platform decides for them. This mirrors a real historical pattern (competing private currencies, market-priced by trust in the issuer) rather than being an invented gimmick.

A reputation layer built from arithmetic, not a hidden score

How often you mint responsibly, how much of your own currency you hoard versus let circulate, how often your trades and mints get disputed and retracted — all of it is plain, hand-checkable arithmetic over the ledger and the claim graph above, like a public credit report built from the numbers, never a black-box number nobody can audit. When a mint gets disputed and voted down, it ripples through to your own reputation automatically, the same way an unwound claim ripples through its dependents.

A listings marketplace, on the same ledger and claims

People can list an item for sale, buy it outright, or bid at auction. Payment moves into a neutral escrow first and only reaches the seller once delivery is confirmed — or automatically, after a wait, if the buyer never gets around to confirming. A disputed order is settled by the exact same claim-vote mechanism as everything else on this platform, not a bolted-on customer-support process.

Resilient storage underneath all of it

Records are split into pieces and spread out with a bit of built-in redundancy — the same mathematical technique real-world cloud backup services use — so the system can lose a portion of where those pieces are stored and still reconstruct the full, exact record. This was proven, not assumed: pieces were deliberately taken away in testing, and reconstruction was confirmed to work right up to the point it honestly should fail, and to fail loudly, not silently, past that point.

Neither the dependency-tracking nor the contradiction-flagging is a fully solved research problem — the deeper academic versions of both ideas have been studied since the late 1970s and are still active research — and this project isn't claiming to have solved them. What's built is a working, tested version of the practical, useful slice of each idea.

Communities can now set some of their own platform rules

the site stops deciding value-affecting rules for everyone

Two small but meaningful decisions used to be hardcoded the same way for every community on the platform. Neither is a technical detail — both are rules that affect who gets what, and until now the platform itself decided them for everyone, the same way, whether a community liked it or not. That's changed: each community can now vote, using the exact same claim-and-vote mechanism as everything else here, to set its own value for either rule. If a community never votes, a sensible default keeps things working exactly as before. This matters for the same reason everything else here is built the way it is: the platform should be a neutral place communities run themselves on, not something that quietly makes value-affecting decisions on their behalf.

Delivery timeout

How long an unconfirmed delivery waits before payment auto-releases to the seller — a community can vote its own value in, instead of accepting the platform's fixed default.

Currency valuation mode

How a currency's "real" value is worked out when someone pays with a mix of several currencies — a community can vote to change how that's calculated for their own members.

A couple of further rules in the same spirit — how large a majority is needed to pass a vote, how long someone has to appeal a decision — have been identified as good future candidates for this same treatment, but aren't built yet, noted here rather than left unsaid.

Keeping decisions, and the voters behind them, honest

accountability, not just voting

Roles a community defines, grants, and can vote back out

There's no fixed list of roles built into the platform — a community proposes a role (a name plus a plain description of what it's for) the same way it proposes any other claim, grants it to specific members, can depose one person from it without touching anyone else, or dissolve the role entirely (which automatically pulls every current holder's grant along with it, for free). Proposing someone's removal triggers a full, honest public audit of everything they've done on the platform — nothing private, since nothing on this platform is private to begin with. Worth being plain about one thing: a role here is a badge of community recognition, not a technical permission — the platform doesn't stop a non-holder from acting as if they held one, matching this platform's oldest rule of no passwords, no accounts, no technical gatekeeping anywhere.

Appeals now apply to any decision, not just marketplace disputes

The appeals process that already existed for marketplace disputes has been pulled out into a general capability any part of the platform can reuse. A vote to remove someone from a role, or to dissolve a role entirely, can now be appealed too, with a second community vote able to reverse it — the identical mechanism already proven for marketplace disputes, nothing new invented, proven with a real test before being called done.

A new, honest accountability score for voters themselves

Once a decision can be reversed on appeal, it's worth asking whether a given voter has tended to be on the side of decisions that later got reversed. A new, separate score answers this, built with the same hand-checkable-arithmetic standard as every other score here. Two safeguards stop it punishing honest disagreement: a reversal only counts if the appeal that reversed it passed by a clear, decisive margin, and even then it's weighted by exactly how decisive it was. Kept deliberately separate from a member's main reputation score, so people aren't afraid to vote on anything contested. It exists as a number the system can compute today; it isn't shown on the website yet.

Flagging suspicious activity, honestly

Anyone can flag an account, a currency, or a specific decision as suspicious, with a required real reason — it's just another claim, so it automatically gets a vote, the same "unwind" behaviour, and the same appeals process as everything else. Alongside that, a genuinely new set of honest numbers (how often a group of accounts has voted together, whether their combined vote was actually decisive, how tightly their votes cluster in time, whether they have any other real activity at all) helps a human decide whether a flag is worth raising — never an automated verdict, and never scanning the whole community looking for "suspicious" groups on its own. Proven, not just claimed: tested side by side against two real, independent members who simply agree often, and shown to tell the two cases apart.

Trust you can check, currency by currency

should I trust this coin, not just this person

A trust score for one specific currency

The reputation layer above answers "should I trust this person's conduct." A related but different question: before accepting payment in one specific member's self-minted currency, how much should you trust that coin, specifically — how widely it's actually held by other people, how often it changes hands, how concentrated current holdings are, and its own dispute history. Shown on the wallet page (comparing every currency side by side) and directly on a listing's price, so the question gets answered right where the decision actually gets made. It was also checked, plainly, whether this score is easy to game — and two of its parts were: how many people hold a currency and how often it trades, both of which could be cheaply faked by shuffling currency back and forth with a second account. That's now detected and penalised, while genuine repeat trading between two real partners is left completely untouched.

Paying with a mix of several people's currencies

A buyer can now pay for a listing using a mix of several different members' currencies in one purchase, instead of being forced to hold enough of just one — each currency in the mix valued by its own trust score at the moment of the trade. The whole basket moves together, all at once, or not at all: if a buyer's proposed mix doesn't quite cover the price, or they don't actually hold enough of one currency they offered, nothing moves, not even the part they could genuinely afford. This was deliberately tested by trying to break it first. A single-currency payment (the normal case) is just a basket with one item in it, so nothing changes for someone who doesn't need this.

The marketplace

a real place to browse, buy, sell, and dispute

Listings, escrow, and auto-release

Sellers list an item fixed-price or as an auction; a buyer's payment moves into escrow first and only reaches the seller once delivery is confirmed. Auctions settle themselves at their deadline to the highest genuine bid, and an order whose buyer never confirms delivery auto-releases to the seller after a set waiting period — no person has to click anything, so a forgetful buyer can't trap a seller's payment forever.

Richer disputes: counter-claims, evidence, appeals

A seller can file a structured rebuttal, either side can attach evidence, and — as above — a resolved dispute can now be appealed once, with a second community vote able to reverse the original payment decision. Proven both ways in the demo: one dispute upheld (payment returned to the buyer) and one rejected (payment released to the seller anyway), using the real voting mechanism, not a placeholder.

Auctions, negotiation, watchlists, and questions

A buyer can offer less than the asking price and the seller can accept, reject, or counter over any number of rounds; anyone can watch a listing and see it update even after it sells or is withdrawn; and every listing has a public question-and-answer thread. All of it, plus browsing, buying, bidding, and managing a wallet, runs through a first real web interface — a place to actually click through, not just read about — where a visitor can switch between entirely separate communities from within the page itself, demonstrating live that different communities get their own fully isolated world.

Two honest recommendation strips

Every item's page shows other currently-for-sale items that share its category, price range, or wording — an honest, plainly-labelled keyword match, not a claim of understanding meaning the way a human would. The main browsing page also shows a personalised "recommended for you" strip built from what you've actually watched, bid on, and bought — weighted so a genuine purchase counts for more than an idle watch. If you haven't interacted with anything yet, you correctly see no personalised recommendations at all, rather than a list dressed up to look personal when it isn't.

How it's built

current work, and what came before it

Current — claim graph, ledger, reputation, governance, marketplace

Built off-chain, on Evaluated Applications' own EvalApp (orchestration) and HoloDb (storage) libraries — deliberately no blockchain dependency in this part of the project, at your direction. Underneath the ledger sits a resilient storage layer using the same redundant-piece technique real-world cloud backup services use. Ahead of the exact (and comparatively expensive) reconstruction, a quick approximate check — borrowed from our own Phasor pattern-matching library — flags a corrupted piece fast, before bothering with the full rebuild. Each block's header also carries a compact fingerprint of its own contents baked in alongside its tamper-evident hash.

Multi-tenancy — separate communities, kept fully apart

Different communities using this platform each get their own completely separate claim graph, ledger, and reputation data — hard-partitioned, not just filtered by a hidden flag — so one community's records can never leak into another's, even if two communities reuse the exact same names or IDs for things. Proven with a demonstration where two communities deliberately reuse identical names throughout and never interfere with each other.

A first proof pieces can travel over a real network

Several small, independent programs were run at once on one machine, each holding only its own slice of a record, and a separate program fetched pieces from them over real network connections and rebuilt the full record from what it received. When some of those programs were deliberately shut down mid-test, the requester correctly noticed they'd gone quiet and honestly reported it couldn't rebuild the record rather than guessing. This is a genuine step up from proving the storage layer only inside one program's memory — but it is not yet real multi-machine deployment, see "Not built yet" below.

Historical — the token & governance work

The original recycling-token idea — a digital token that could be minted for approved recycling activity, built on OpenZeppelin's audited, industry-standard building blocks rather than anything custom-written — was built and tested (15 automated tests), along with a small .NET bridge service that could trigger a mint and confirm it landed (9 automated tests). Neither has been deployed to any live test network. This work still exists and still passes its tests; it simply isn't where current effort is going.

"Verification" and moderation remain, and will remain, manual/human decisions where they apply — this project has never claimed and does not claim to have automated trust or fraud detection. Where a human judgement call is needed, a person makes it; the platform just tracks the consequences honestly.

A dropdown that looked fine but didn't work

found and fixed before it caused a problem

Worth being direct about this one, precisely because it's the kind of thing that would have been embarrassing to hit live in front of someone. A recent internal change to how the website's pages are built accidentally left two controls at the top of every page — the "which community am I in" and "who am I acting as" drop-down menus — looking completely normal (they rendered, they had the right options in them) while silently not responding to being clicked or changed. Everything else on the site kept working normally; only those two header controls, and the small "create a new one" forms tucked inside them, were affected. This was caught by a dedicated review built specifically to check "does every clickable thing on this site actually sit somewhere the site is prepared to receive a click," not by someone noticing it by chance — and once caught, it was fixed the same day, with an automated check now permanently in place that would fail loudly if the same category of mistake ever crept back in.

Checked today, live, as part of this review: it's fixed, and stays fixed. Disclosed here deliberately rather than smoothed over — this preview's whole point is to be honest about what's real and what still needs work.

Current status

honest, as of this preview

Built and tested

Everything in the sections above — the claim graph and its "unwind" behaviour, contradiction-flagging, the currencyless ledger with minting/trading/redemption, the resilient redundant-piece storage layer, the reputation and per-currency trust scores (with wash-trade detection), community-defined roles/deposition/dissolution with a public audit trail, appeals for any decision, voter accountability, suspicious-activity flags with honest coordination signals, community-set platform rules, basket payments, and the full marketplace (listings, escrow, auctions, negotiation, watchlists, messaging, both recommendation strips) — is proven end to end with automated tests and runnable demonstrations against real (if locally-hosted) storage. The actual website was also driven over real HTTP as part of this review pass — browsing, a listing page, selling, orders, wallet, watchlist, and a broken link — confirming the pages people would actually see work, not just that the underlying code compiles.

Not built yet

The web interface hasn't yet been driven through an automated browser click-through of every button end to end — every control has been checked by loading the page and confirming it calls the same tested backend the automated tests already exercise, but no browser-automation tool is available in this working environment, so this stays a known, flagged gap rather than a silently skipped one. No blockchain involvement in the new work, at your direction. No real multi-machine deployment — the networking proof still runs everything on one machine. "Verification" and moderation remain manual/human decisions by design, not an automation gap. No growth, referral, or "invite a friend" mechanics anywhere — deliberately out of scope, same as before the pivot.

Evaluated Applications' role

Evaluated Applications is building RecycleDAO end to end: the claim graph, the currencyless ledger, the reputation and per-currency trust layers, the resilient storage underneath it, the governance layer (roles, deposition, appeals, voter accountability, suspicious-activity flags), and the marketplace built on top of all of it — proven working off-chain on our own EvalApp, HoloDb, and Phasor libraries. Since the last preview, that work has grown to include community-set platform rules, basket currency payments, and a single entry point that opens the whole platform at once, plus a real fix — found by a dedicated review, disclosed here rather than hidden — for a header-control bug that silently stopped responding to clicks. The original token-and-blockchain work is complete for what it covered and still passes its tests, but is not the current focus. The next steps are an automated browser click-through of the web interface, and, separately, a decision about whether and how to build genuine multi-machine network deployment.
