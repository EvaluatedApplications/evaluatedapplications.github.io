RecycleDAO — a recycling-incentive DAO, in progress

This page is a private preview prepared for Antonio to track progress on RecycleDAO: a technical proof of concept for a token-and-governance layer over recycling activity, built by Evaluated Applications. It is a testnet-only demonstration — not live, not fundraising, and no real monetary value changes hands anywhere in this build.

Status: token contract + minter service built, tested locally Not yet deployed to any testnet Not live · no real value Prepared for Antonio

What RecycleDAO is

the concept, in plain language

RecycleDAO is a proof of concept for tying recycling activity to a token-based reward and governance system. In the intended flow: a participant submits evidence of a recycling activity, a reviewer approves it, and an approved submission mints a reward token to the participant. Holding the reward token also carries voting weight in a DAO — token-weighted governance over shared decisions. The goal of this build is to demonstrate that mechanism working end to end on a public test network, cleanly and honestly, before any conversation about a real deployment.

How it's built

two halves, cleanly separated

On-chain — the token & governance

Solidity contracts, built with Foundry on top of OpenZeppelin's audited, industry-standard building blocks rather than hand-rolled security logic: an ERC-20 reward token with voting and permit extensions, a Governor contract for proposals and votes, and a Timelock that adds a delay before anything governance approves actually executes. Minting the reward token is gated to a single authorised address — never open or public.

Off-chain — the service

A .NET service that bridges a "this submission was approved" event to the chain: it calls the token contract to mint the reward, then reads back the recipient's balance to confirm it landed. A library called Nethereum is the only piece that touches the chain directly — it holds a testnet-only signing key and submits the mint transaction — kept behind an interface so the rest of the logic is fully testable without a real network. The full intake/verification pipeline is planned to run on Evaluated Applications' own EvalApp (orchestration) and HoloDb (storage for submissions, decisions, and the reward ledger) in a later milestone.

The "verification" step in this proof of concept is a manual reviewer action, not an automated fraud-proofing system. Real-world chain-of-custody for physical recycled goods is a genuinely hard, open problem — this build does not claim to solve it, only to demonstrate the token/governance mechanism that would sit downstream of a real verification process.

Current status

honest, as of this preview

The first milestone's code is written and tested — but nothing has touched a public network yet. The reward-token contract (RecycleToken, an ERC-20 with voting and permit extensions on top of OpenZeppelin's audited building blocks) compiles and passes 15 out of 15 automated tests, run entirely on a local, throwaway test blockchain. A companion .NET service that can mint the token and read back the resulting balance is built and passes 9 out of 9 automated tests of its own, using a stand-in for the real network connection. Both halves are proven to work in isolation. What hasn't happened yet is putting either of them on a real (if free/test-only) public network — that step needs an RPC endpoint and a funded test wallet that only Antonio can supply (see the status brief for exactly what's needed). Once that's in hand, the remaining work is a short live demo, not more engineering.

Built and tested (locally)

The reward-token contract with its mint gate (15/15 Foundry tests passing) and a .NET service that can call it and read back a balance (9/9 xunit tests passing, mocked chain client). Neither has touched a real or public test network — both are proven only in local, throwaway test environments so far.

Not built yet

Deployment to a live public testnet (blocked on an RPC endpoint + funded test wallet from Antonio — nothing we can fabricate), DAO governance contracts (Governor/Timelock), the real submission and verification pipeline, any user-facing interface, and anything resembling a multi-user flow.

Evaluated Applications' role

Evaluated Applications is building RecycleDAO end to end: the on-chain contracts, the off-chain service, and the bridge between them, using its own EvalApp and HoloDb libraries for the off-chain half.
