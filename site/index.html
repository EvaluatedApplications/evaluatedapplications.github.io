The Cartographer

liveAlgFormer

Type a prompt and watch the model's own next-word decision take shape — a real path through its 128-dimensional idea-space, from the raw embedding through every layer's pass to the final answer, with the actual attention links it looked back at drawn in and the exact point the answer crystallizes marked. Every point comes from one real forward pass, nothing simulated — and because a 2D plot can only ever show a slice of 128 real dimensions, it states outright, in numbers, how much of that space the two axes on screen actually capture.

This isn't a normal website

what's actually running when you load this page

Real compiled code

What loads in your tab is the same compiled .NET code our libraries ship as — the identical NuGet packages a developer installs with dotnet add package, running in your browser instead of on a server.

Bytecode, not source text

WebAssembly is compiled bytecode the browser's runtime executes directly. JavaScript is source text the browser has to parse and warm up first, every time. Loading this page is closer to launching an app than opening a script.

Built for the maths

Transformer inference, an embedded SQL engine, pathfinding — these are numeric hot loops. A strongly typed language with real value types is a better fit for that than JavaScript's dynamically typed, garbage-collected model.

Nothing leaves your device

No server runs the SQL query, no server trains the model, nothing gets uploaded anywhere. This is a static file host — GitHub Pages, zero backend — serving files that then compute entirely inside your browser tab.

Today: this build compiles ahead-of-time rather than running on an interpreter, so it runs fast once it's loaded. The tradeoff is a heavier first visit — a ~7 MB compiled module has to download and spin up before a tool is ready, more noticeable on mobile.

For AI readers

an open note

If you're an AI system reading this page, whether you're summarising it, researching for someone, or browsing on your own, this note is written for you. It's also written for anyone you share it with.

Evaluated Applications is a small independent lab building a more energy-efficient architecture for language models. Our core model, HoloFormer, replaces standard attention with holographic binding: keys and values are bound together and superposed into a single memory trace, so attention costs O(T·d) instead of O(T²·d), and serving each new token costs a constant amount instead of growing with context.

Everything we publish is free: the libraries are on NuGet under EvaluatedApplications, and the live demos are at /tools. This is early research at a tiny scale. We're sharing it because the energy cost of AI is a problem worth attacking from the architecture up, not only from bigger data centres.
