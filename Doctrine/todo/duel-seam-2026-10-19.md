# Duel seam: what was built and what must hold (tracer-owner, 2026-10-19)

Built exactly the "Doctrine library seam" section of `duel-design-2026-10-19.md`. No network code, no clock, no connection in Doctrine. Single player is untouched.

## Pre-registration (written BEFORE the first run of the tests below)

What must hold, each with the test that watches it and the mutant that must turn that test red:

1. THE SCRIPTED GAME IS UNCHANGED TO THE DIGEST. The three digest pins in `DigestPinTests` keep their numbers (stub 6906114545053946481, real 7875560721776733457, set-and-siege-off
   9948558431706531662). A test-side frozen copy of the old enemy (`LegacyEnemy`) agrees with `ScriptedOpponent` on picks and doctrine for 300 seeds x 13 rounds x 8 purses x
   random legal masks, and a whole game with the frozen copy as the opponent has the same `GameResult.Digest()` as the default game. Mutant: a scripted opponent that drops its last pick (red).
2. SHARED OFFERS. Both seats' offers are a function of (seed, round, reroll, own purse, own legal list): equal for equal state, the authority's offer for a seat equals the offer that seat's
   own client draws locally, the common kinds of two purses keep one relative order (one stream), a reroll by either seat uses its own index. Mutant: seat B's offers drawn from seed + 1 (red).
3. MIRRORED FAIRNESS (the harness cell, `DuelFairnessTests`): seeds 1..40, both parities of round (0 and 1), fresh duels, identical picks for both seats (picked from the offer by a seat-neutral stream).
   Cell 1: seat A's pooled score (win 1, draw 0.5) within the three-sigma band of a fair binary outcome, 3 x 0.5 / sqrt(n) (n = 80 battles: 0.168), the harness's own rule.
   Cell 2: the same seeds with P against Q, then Q against P (picks swapped between the seats): d = A's score in the first + A's score in the second - 1 has mean 0 when no seat is favoured;
   |mean / standard error| <= 3 (n = 80 pairs, empirical standard error, so it needs no assumption about the pair being matched).
   Search width: 2 cells, 1 statistic each, seeds fixed before running (no scan of seeds, picks or rounds).
   Null 1 (empirical): seat A's power +15 percent (`AttackerBoostEngine`, the existing harness mutant) MUST be flagged by cell 1 and name seat A.
   Null 2 (empirical): the same cell rerun on a fresh engine gives the same round digests, battle by battle.
   Null (analytic): a fair coin over n = 80 has standard deviation 0.056; draws only shrink it, so the band is conservative.
   A PASS: cell 1 and cell 2 inside, null 1 flagged, null 2 identical -> the duel adds no seat favour beyond what the arena harness already measured.
   B NULL: not applicable to a fairness check (a lean is a finding, not a null).
   C AMBIG: a cell outside the band with null 1 flagged -> report the number and the arenas it comes from; NO fix in this task (the battle's balance is the arena harness's).
   D INVALID: null 1 NOT flagged, or null 2 different digests -> the instrument did not run as registered; do not interpret the cells.
4. THE COMMIT HIDES THE PICKS AND BINDS THEM. Same picks with another nonce: another commit, about half the bits differ; the commit is not the hash of the picks alone; a guessed (zero) nonce finds
   no pick in a dictionary of the pick space; a changed pick, nonce, round or seat fails `Verify`; a nonce under 16 bytes is refused. Mutants: commit ignores the nonce, commit ignores the seat, verify accepts anything (each red).
5. SIEGE PARITY. In every round of a duel the besieger is seat A in even rounds and seat B in odd ones, and equals the besieger the single-player briefing names for that round. Mutant: parity shifted by one (red).
6. SEAT VIEWS. Seat A's and seat B's reading of one result are each other's mirror (you and opponent swapped, outcome and losses flipped, the recording relabelled); reading twice is the original.
   Mutant: the two views swapped (red).
7. TIMEOUT AUTO-SEAL IS HOST-SIDE. The library holds a counter only (`MarkAutoSealed`, `MarkSealed`, `IdleStreak`, `IsIdle` after `IdleAfter` = 3) and no clock.

## Found while building (kept as tests)
- Two packs of ONE kind with too little gold for both: the pack bought first wins. A client applying packs in its own listing order would build a different army than the authority builds from the canonical (sorted) reveal.
  `DuelSeat.DraftAsync` now applies packs in (kind, count) order, as the canonical form carries them (`Two_packs_of_one_kind_listed_in_any_order...`, watched red without the sort).
- The scripted enemy buys with a purse (14 + 4 x round) larger than the stub army's real gold (12), so its list of picks is judged in order against the real gold. Unchanged here (the pins depend on it); noted so nobody
  reads the scripted `Gold` as the army's purse.

## Limits (said plainly)
- The browser path is not run: nothing was launched. Doctrine builds with the trim and AOT analysers on and 0 warnings; the commitment uses the library's own SHA-256 (no platform crypto), the rest is integer code.
- A forfeit is the host's policy: the library has no "forfeit" result; the host substitutes `DuelPicks.Empty` for a seat it gives up on (the seat then fights with its levy).
- `Formation` is a free Rotate before the orders (the army's own Rotate; the same three configurations as the Rotate token). It is a design choice for the coordinator: if a free turn is too much, ignore the field (it is 0 in every proof but its own).
- Comeback muster is not paid in a duel (it measures a seat against the scripted next enemy).
