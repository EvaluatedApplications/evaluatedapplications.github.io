HoloDb · holographic SQL database

A database that doesn't scan.

Same SQL, same data, results verified identical to the row — HoloDb against DuckDB and SQLite, up to 10 million rows. HoloDb keeps its aggregates as maintained holographic accumulators, so SUM, COUNT, GROUP BY, MIN/MAX and DISTINCT answer in constant time instead of reading the table. Aggregates don't grow with the table

The whole story in one shape. As the table grows 100× — from 100K to 10M rows — DuckDB and SQLite have more rows to read, so their times climb. HoloDb reads a fixed-size accumulator, so its line stays flat on the floor. Both axes are logarithmic.

Where DuckDB wins, and why HoloDb wins

DuckDB is still ahead on four

An honest benchmark shows the losses. At 10M rows DuckDB beats HoloDb on:

  • GROUP BY int, SUM of a real column — ~9× slower. Real-valued group sums are HoloDb's weakest path (the constant-time trick is exact-integer only).
  • filtered COUNT(*) and SUM of a real column — DuckDB's vectorized scan is ~2× quicker.
  • ORDER BY … LIMIT 20 — top-K isn't specialised in HoloDb yet.

DuckDB is a mature, world-class analytics engine. HoloDb is young. That it wins 11 of 15 anyway is the point.

Why the wins are so large

HoloDb doesn't compute aggregates by reading rows. Integer columns feed CRT bind-accumulators — a holographic running SUM/COUNT per group, maintained on write — so a whole-table SUM or a GROUP BY is a fixed-size vector read, independent of row count. Scans use a columnar store with compiled predicates and per-block zone-maps that skip blocks that can't match. The aggregates are exact, not sampled.

How it was measured

Nothing here is cherry-picked from a lucky run. The harness loads the same rows into all three engines via each one's idiomatic bulk path, verifies every result is identical to the row, then times the median of repeated runs. Consumption is like-for-like: every value is read typed — no boxing — through each engine's fast accessor, so what's timed is the engines, not the client glue.

Measured on an Intel Core i9-11950H (8 cores / 16 threads), 32 GB, .NET 8, in-memory tables, ServerGC. SQLite via Microsoft.Data.Sqlite, DuckDB via DuckDB.NET. Your numbers will vary with hardware; the shape won't.
