Install and first query

Add the package from NuGet with dotnet add package EvaluatedApplications.HoloDb. You create tables and write SQL. Tables are typed columns, in memory or on disk.

With no WalPath the database is in memory. A WalPath in the options makes it durable. For a database whose tables can be larger than memory, set both WalPath and Paged = true. Paged = true without a WalPath throws.

C#
using HoloDb;

var db = new HoloDbService(new HoloDbOptions());
db.Execute("CREATE TABLE users (id INT PRIMARY KEY, age INT, name TEXT)");
db.Execute("INSERT INTO users VALUES (1, 30, 'Ada')");

var result = await db.ExecuteAsync("SELECT name FROM users WHERE age >= 18");
foreach (var row in result.Rows) Console.WriteLine(row["name"]);
// Ada
Output
Ada

SQL dialect: Standard and Extended

HoloDb accepts the SQL standard and its own statements by default. This is SqlDialect.Standard, and every example on this page runs on it as written.

Vendor spellings are the Extended dialect, opt-in: new HoloDbOptions { Dialect = SqlDialect.Extended } for a HoloDbService, or Database.Dialect on the engine. The HoloDb.Server program takes --dialect extended; its default is standard. A client has no dialect setting of its own: the server decides which SQL it accepts.

Extended adds only
LIMIT, ILIKE, CREATE INDEX and DROP INDEX (with USING KEYED), SHOW (other than SHOW SUMMARIES and SHOW SEQUENCE), DESCRIBE, EXPLAIN, IF [NOT] EXISTS, INSERT ... ON CONFLICT (pk) DO UPDATE, BEGIN, the % operator, and the functions CONCAT, REPLACE, LENGTH, SUBSTR, LEFT, RIGHT, ROUND, TRUNC, SIGN, NOW, DATE_TRUNC, REGEXP_REPLACE, STRING_AGG, MEDIAN, BOOL_AND, BOOL_OR, STDDEV and VARIANCE.
Both dialects
HoloDb's own statements: NEAREST (with its own LIMIT k), AS OF, SET summaries, SET indexes, SHOW SUMMARIES, CREATE SUMMARY TABLE, and APPLY SUMMARY.
Refused by name
A statement that uses an extension under Standard is refused with SQLSTATE 0A000, code extension-disabled, and a message that says how to enable Extended. A name that is in neither dialect, for example STRPOS, IIF, TRY_CAST, ARG_MAX, DATE_DIFF, STRFTIME or REGEXP_MATCHES, is an unknown function.
Checked text
The check runs on the text of each statement sent to the public Execute calls. Statements the engine writes for itself and the replay of the log are not checked, so a log written by an Extended database opens under Standard.

Tables and statements

The answer to every SQL statement is exact. A table has one PRIMARY KEY, of type INT or TEXT. Type names are INT (also INTEGER), TEXT (also VARCHAR and STRING), REAL (also FLOAT, DOUBLE and DOUBLE PRECISION) and DECIMAL(p, s) or NUMERIC(p, s). A bare DECIMAL is refused. There is no BOOLEAN; use INT 0 or 1. Column DEFAULT in CREATE TABLE, UNIQUE, CHECK, REFERENCES and generated keys are refused by name. A composite key is refused.

A column holds SQL NULL only when it is declared NULL. A primary key is never NULL. An INT column takes a whole number in the 64-bit range; 2.5, a number past 64 bits or a text that is not a number throws. A REAL column takes any finite number. Integer arithmetic in a SELECT that would pass the 64-bit range throws for the rows the query keeps.

Joins
INNER JOIN runs on the engine's join routes: an in-memory database accepts several in one statement, a paged table one. LEFT, RIGHT, FULL, CROSS and every other join runs on the row engine. A join over a paged table with NULL columns runs with SQL NULL rules.
Exact sums
INT sums are exact 128-bit running totals, and a statement throws if the true total leaves 64 bits. Empty selections give NULL for SUM, AVG, MIN and MAX, and 0 for COUNT. COUNT(*) and AVG count the rows that exist.
Row order
Without ORDER BY, the order of rows is unspecified and can change after a DELETE or a write that moves a row.
Analytic tables
SMALLINT, INTEGER, BIGINT, DATE, TIMESTAMP, CHAR(n) and VARCHAR(n) columns, or a table with no primary key, make an analytic table. It exists only in a paged database and has no NULL columns. Load it column by column with BulkLoadColumns.
Refused, not reinterpreted
A statement that would otherwise drop one of its clauses throws. DISTINCT together with an aggregate is refused (use GROUP BY), and so is NEAREST combined with a join, GROUP BY, HAVING, ORDER BY, DISTINCT or an aggregate.
Statements for tables and data

Exact decimals

DECIMAL(p, s) and NUMERIC(p, s) hold exact values of at most 18 digits in total, with 1 <= p <= 18 and 0 <= s <= p. The value is stored as a scaled 64-bit integer. A decimal literal is exact up to 15 significant digits; a longer literal is refused by name.

Arithmetic
+, -, * and / on decimal values are exact. A result is rounded half away from zero to the scale it needs. A result that does not fit 18 digits throws SQLSTATE 22003. Division by zero throws 22012.
Writes
A value written to a decimal column is brought to the column's scale. A value that does not fit the column's digits throws 22003. Text input to a decimal column is refused.
Results
A decimal result comes back as a System.Decimal with its scale, and QueryResult.ColumnScale gives the column's scale. A decimal with an integer is a decimal. A decimal with a double is a double.
Works on in-memory and paged tables
Decimal literals and columns in expressions and WHERE; INSERT; UPDATE and DELETE whose WHERE names no decimal column; SELECT with aggregates, GROUP BY and HAVING (SUM keeps the scale, AVG returns a decimal); DROP TABLE, SHOW and DESCRIBE.
Refused by name for a table that holds a decimal column
A join over it; NEAREST over it; an UPDATE or DELETE whose WHERE names a decimal column; Seal, KeyDigest, EnablePleroma, BulkLoad, BulkLoadColumns, PagedBulkLoad, ApplyChanges, and a read AS OF a past sequence. SQLSTATE 0A000.
Refused at definition
A bare DECIMAL (0A000); p above 18 (0A000); p below 1 or a scale outside 0..p (42601); a DECIMAL primary key; a DECIMAL column in a summary table; an ADD COLUMN of a decimal with a DEFAULT other than NULL.

Structures that build themselves

Nothing here is declared. The engine watches the workload it serves and builds only the structures that repeated queries have paid for: summaries, sorted and keyed indexes, a tree of exact sums, learned block records with exact partial sums, learned routes, zones that skip blocks, top-k by zones, gather and placement. It drops them when the workload moves on or when a write would make them cost more than they save. One budget covers them all and is a hard cap.

SET indexes and SET summaries choose whether automatic indexes and summaries are built (auto), only declared ones are kept (declared), or none answers a query (off). EXPLAIN says which structure answered a statement, or why none did, and SHOW SUMMARIES reports the state of each structure and what it is waiting for. The answers are the same in every setting.

NULL

Declare a column NULL and it holds true nulls with three-valued logic, on paged tables as well as in memory. A statement that names a nullable column takes an exact path that reads only the columns it names. Null counts are maintained.

Three-valued logic
WHERE and HAVING keep a row only when the predicate is true. A comparison, LIKE, IN or BETWEEN on a NULL is unknown. IS NULL and IS NOT NULL are always true or false.
Aggregates
COUNT(*) counts rows. COUNT(col), COUNT(DISTINCT col), SUM, AVG, MIN and MAX use the non-NULL values, and are NULL when there are none.
Grouping and ordering
GROUP BY and DISTINCT make one group of all the NULLs. ORDER BY puts NULL first when ascending and last when descending. An INNER JOIN never matches a NULL key.
Results
Read a NULL cell with Rows or GetValue, where it is DBNull.Value, or test QueryResult.IsNull. GetLong, GetDouble and GetText throw a HoloException on a NULL.
Literal NULL in a comparison
On a SELECT, a literal NULL beside =, <>, <, >, <=, >=, IN, BETWEEN or LIKE is unknown. In a DELETE or UPDATE WHERE, the same literal is refused by name, with a message that says to write IS NULL.

Similarity search

NEAREST ranks rows by the cosine similarity of their holographic encoding to a partial key: any subset of columns, of any type, in the form SELECT ... FROM t NEAREST (col = value, ...) [WHERE ...] [LIMIT k]. The encoding is derived from the columns, so a row is ranked by the values it holds now. A WHERE filters the rows before they are ranked, and no index has to be declared.

Similarity is graded. A number or date close to the key ranks ahead of a far one, and a text value that is nearly the same string ranks ahead of an unrelated one, by character trigrams. Add score to the projection to read the ranking value; 1.0 is an exact match. Above a size threshold the ranking uses an approximate candidate search (locality-sensitive hashing) instead of comparing every row, so its order can differ from an exact scan. NEAREST does not combine with a join, GROUP BY, or a table with a decimal column.

C#
using HoloDb;

var db = new HoloDbService(new HoloDbOptions());
db.Execute("CREATE TABLE products (id INT PRIMARY KEY, category TEXT, price INT)");
db.Execute("INSERT INTO products VALUES (1,'electronics',100),(2,'electronics',120),(3,'furniture',300)");

var near = db.Execute("SELECT id, category, price, score FROM products NEAREST (category = 'electronics', price = 118) LIMIT 2");
foreach (var row in near.Rows) Console.WriteLine($"id={row["id"]} category={row["category"]} price={row["price"]} score={row["score"]:F3}");
// id=2 category=electronics price=120 score=0.993
// id=1 category=electronics price=100 score=0.988
Output
id=2 category=electronics price=120 score=0.993
id=1 category=electronics price=100 score=0.988

Transactions and durability

START TRANSACTION, COMMIT and ROLLBACK (BEGIN under Extended) run over a write-ahead log of signed page deltas in a ring file whose size follows the largest recent batch, with group commit: a statement that has returned is on disk. A rolled-back transaction leaves the same rows, though their order may differ. DDL inside a transaction is allowed. BulkLoad is not, and Checkpoint() throws inside one.

On a paged table, a statement that fails inside a transaction undoes only itself, and the statements before it stay. A transaction larger than the buffer pool spills to a scratch file, and a rollback or a power cut leaves the table as it was. Every commit is checksummed, and the table that opens after a cut is the table before or the table after.

How it is tested

AS OF and Seal

Paged tables keep each committed change as a signed record, so a past state is the present state with the later changes taken back out. SELECT ... FROM t AS OF n reads the table as it was after commit n, and AS OF LATEST is the present state. Seal(table, asOf: n) returns the table's seal as it was after commit n. SHOW SEQUENCE returns the current sequence and the floor.

The answers are exact at every n at or above the floor. Refused by name, never answered approximately: a join under AS OF, NEAREST, an in-memory table, n above the current sequence, n below the floor, n inside a retained segment, and a read inside a transaction that has written the table. An ALTER TABLE ... ADD COLUMN is a barrier: an AS OF read below the floor is refused by name.

Loading data and change batches

ImportCsv(table, path, header, delimiter) loads an RFC 4180 CSV file into an existing table in one atomic load. A bad field refuses the whole file by name, with its line number, and nothing is loaded. It is a method, not a statement, so a SQL client cannot make the server read a file.

BulkLoad and BulkLoadColumns append typed arrays without the SQL parser, and validate every key first, so a duplicate primary key leaves the table unchanged. The bulk load forms refuse a table that holds a decimal column.

ApplyChanges applies a batch of upserts and deletes atomically on an in-memory table: one write lock, one log commit, and a reader sees the table before the batch or after it. Changes count in order, the last change of a key wins, and only the net effect is applied. The SQL form INSERT ... ON CONFLICT (pk) DO UPDATE (Extended) changes only the listed columns of an existing row, and is in-memory only.

KeyDigest(table, modulus) returns one bucket of Count and an exact Int128 Sum for each bucket of an INT primary key, so two systems can compare modulus numbers instead of every key. Seal fingerprints a table so shards add and replicas compare.

C#
using HoloDb;

var db = new HoloDbService(new HoloDbOptions());
db.Execute("CREATE TABLE users (id INT PRIMARY KEY, age INT, name TEXT)");
db.Execute("INSERT INTO users VALUES (1, 30, 'Ada')");

var result = await db.ExecuteAsync("SELECT name FROM users WHERE age >= 18");
foreach (var row in result.Rows) Console.WriteLine(row["name"]);
// Ada
Output
Ada

Tables larger than memory

A paged table keeps its pages in a buffer pool of 8 KB pages, and its changes in a write-ahead log. Pages that are not in the pool are read from data.pages through a read-only memory map. CreatePaged(createTableSql, dir) creates a paged table in a directory, OpenPaged(dir) reopens it and recovers committed state from its log, PagedBulkLoad streams rows and commits every so many rows, and ClosePaged(table) checkpoints and closes one table.

Every page has a logical number, and a block map takes that number to a place in the file. The map changes only inside a committed log batch, so a moved or rewritten page never leaves the file half-changed. Every log block and every data page carries a CRC-32C checksum. A page that fails its checksum throws an error that names the page and the file, with the code data-page-checksum, so a bad page is an error and never a different answer.

A DELETE marks its rows and moves nothing; the cost follows the rows deleted. Consolidation fills the holes after a statement, once the scans that read them have paid for it, and gives the freed pages back. Consolidate(table) runs it now. Rows come back in a different order afterwards unless you ORDER BY.

Whole-database paged mode: HoloDbOptions.Paged = true puts a new database on the paged engine, so a plain CREATE TABLE creates a paged table. Opening an existing text log with paged: true throws.

Storage format and upgrading

The write-ahead log of a paged table, wal.log, is a fixed-size ring of checksummed blocks holding signed deltas. It does not grow with history. The log is format HWAL 5. The table record, table.meta12, begins with the line HoloDb table format 15.

Format 15 records the precision and scale of each DECIMAL column. A store in format 14 opens, and its catalog is written again as format 15 on its next catalog write. A table record of format 13 or older is refused by name. The message says to export the rows with the build that wrote them and load them into a new database.

A build of major version 20 reads only format 14. It refuses a store written by this release (format 15) with a named message. Stores written by major version 20 open in this release. There is no in-place upgrade.

Summary tables and the aggregate plane

A summary table keeps no rows. It stores only an exact aggregate plane, the value dictionaries of its dimensions and the position each feed has reached, so its size depends on the distinct values of its dimensions. A dimension is an INT or TEXT column you filter, group or count distinct on; a measure is an INT column you SUM or AVG. ApplyPlaneChanges takes Add, Remove and Replace changes as one atomic batch, and a batch at or below the position already applied for its source is skipped.

The optional aggregate plane, held in Phasor Pleroma stores, summarises the small-domain columns of one table. It answers WHERE aggregates over its dimensions, multi-column GROUP BY with HAVING, COUNT(DISTINCT dimension), and one equi-join COUNT or SUM. Anything it does not cover goes to the engine, so a statement returns the same rows with the plane on or off. PleromaVerify rebuilds the plane from the columns and compares it. A plane attached with EnablePleroma is not kept across a restart; one created with CREATE INDEX ... USING SUMMARY (Extended) is.

Statement limits, metering and integration

A statement can carry a cancel token, a timeout and a result byte budget through StatementLimits. A cancelled or timed-out statement throws HoloCancelledException, and a statement the budget refuses throws HoloResultTooLargeException before the rows that would pass it are allocated. A stopped statement has no effect.

MeteredDatabase reports the rows and bytes each query read. services.AddHoloDb() registers HoloDb for dependency injection, and an EvalApp context runs it inside pipelines.

Over the network

The same engine runs as a server, and a typed client talks to it over TLS with the same surface as the in-process engine.
