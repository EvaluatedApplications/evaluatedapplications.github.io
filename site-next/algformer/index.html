AlgFormer, small language models in one shared wave, for .NET

Many small models, one shared wave.

A population of small holographic language models that talk through a shared wave, in pure managed code. They never pass wires to each other. They write to the medium and read the medium.

  • Six atoms with split views, 2.99 against 3.38

    Scores are bits per character on 300 held-out windows of the same text, scored at the last position, drawn the same way for every arm, with two seeds per arm. The text is 300,000 characters of Gutenberg prose with a 64-symbol vocabulary. Each atom is a HoloFormer with shifts equal to the width, two layers, trained with the all-positions loss, learning rate 0.01, batch 16, 800 steps at context 64. Six atoms that each see about a sixth of the text and share the medium score 2.99 (seeds 2.96 and 3.02). One atom that sees all of it scores 3.38 (seeds 3.25 and 3.51). The same six atoms without the medium score 4.33, and with every atom reading the whole window they score 2.47.

  • The writer gradient matters, 3.47 against 3.84

    At width 32 (500 steps at context 32) the pair scores 3.47 when the loss reaches the atoms through the notes they wrote, and 3.84 when the writers are frozen. With every atom reading the whole window the pair scores 3.18, and one atom of width 46 reading the whole window scores 3.48.

  • One fused step for all atoms

    AlgFormer.Gpu stacks the atoms as a batch dimension, so every layer, pass, head, reverse and Adam kernel runs once for all atoms. The number of kernel launches per step does not depend on the number of atoms: 261 for two, eight and sixteen atoms at two layers and two passes, against 454 for two atoms and 1,672 for eight on the per-atom path.

  • The atoms are one system on text they never saw

    The eight-atom checkpoint scores 3.607 bits per token on 40 public-domain books outside its training lists, against 3.538 on its training text, with the unigram baseline at 5.661. All 40 books beat the baseline. Switching the medium off takes the averaged atoms to 20.5 bits per token, and silencing one writer costs every reader between 0.34 and 1.05 bits per token.

The pond: one shared wave

Atoms on a golden spiral, each a source and a listener. Choose one to make it write.

What you can build

Each one is in the library today.

  • A population of small models that behave as one system

    Several HoloFormers with no shared weights write into one bundle of damped oscillators and listen to each other's notes. The answer you serve is the average of their logits, and you can train on that combined answer or give each atom its own loss.

  • Parts that see different slices of the same text

    Each part reads its own slice and the parts still agree on the next token through the medium.

  • A viewer for each atom's trajectory

    AtomField.TrajectoryAllPositions returns each atom's state through its layers as plain arrays, so you can watch it move.

  • The same models on a GPU

    AlgFormer.Gpu runs the atoms with all of them fused into each kernel launch.

    See AlgFormer.Gpu

  • A language model inside your app

    Everything is plain double arrays and SIMD compiled into your project. There is no ONNX Runtime, no libtorch, no CUDA toolkit and no Python to ship.

  • Models that grow instead of restarting

    Helpers extend a trained model to a longer context or a bigger vocabulary without training from scratch.

Run it yourself

Two atoms coupled through the shared memory, trained for twenty steps on one window and read back as the mean of their logits.
EvaluatedApplications.AlgFormer
dotnet add package EvaluatedApplications.AlgFormer
EvaluatedApplications.AlgFormer.Gpu
dotnet add package EvaluatedApplications.AlgFormer.Gpu
C#
using PrismFormer;

// Two HoloFormer atoms (width 32, 2 layers, vocabulary 16, context 8), coupled through the shared memory.
var field = AtomField.Create(atoms: 2, dim: 32, layers: 2, vocab: 16, context: 8, seed: 1);
field.Coupling = AtomCoupling.Memory;

// One example is one token window per atom (at most context + 1 tokens, the same length for every atom).
var examples = new List<int[][]> { new[] { new[] { 1, 2, 3, 4, 5, 6, 7, 8 }, new[] { 1, 2, 3, 4, 5, 6, 7, 8 } } };
double loss = 0;
for (int i = 0; i < 20; i++) loss = field.TrainStepAllPositions(examples, lr: 0.01);

var result = field.InferAllPositions(examples[0]);   // result.Logits is the mean of the atoms' logits
Console.WriteLine($"loss={loss:F3} logits={result.Logits.Length} atoms={result.AtomLogits.Length}");
Output
loss=0.160 logits=16 atoms=2

This is the complete program, compiled and run against the library source. The atom field is opt-in: Coupling defaults to Sum, so set Memory for the shared medium.

A single model takes the same shape. Define a model, train it on pairs of context and target, then predict, read the logits or generate.

C#
using PrismFormer;

// Define a model. Tokens are ints; bring your own tokenizer or encoding.
var model = new AlgFormer(vocab: 16, shifts: 4, layers: 2, maxContext: 6, dModel: 32, frozenPrefix: 0);

// Train on (context tokens, target token) pairs.
var data = new List<(int[] Ctx, int Target)>
{
    (new[] { 1, 2, 3 }, 4),
    (new[] { 2, 3, 4 }, 5),
};
var trainer = new PrismTrainer(model);                 // data-parallel, run through EvalApp
double loss = trainer.TrainEpoch(data, batchSize: 2, lr: 5e-2, shuffleSeed: 1);

// Run inference.
var context = new[] { 1, 2, 3 };
int next        = model.Predict(context);                                    // argmax next token
double[] logits = model.LogitsFor(context);                                  // full logits
int[] generated = model.Generate(context, maxNewTokens: 5, temperature: 0.8, seed: 1);

Console.WriteLine($"loss={loss:F3} next={next} logits.Length={logits.Length} generated=[{string.Join(",", generated)}]");
Output
loss=2.776 next=4 logits.Length=16 generated=[3,1,7,12,10]

Swapping in the holographic core is the same shape. This program trains a HoloFormer, serves it through the incremental cache, and reads what the final query resonated with.

C#
using PrismFormer;

// The holographic core has the same constructor shape. Swap the type, keep the workflow.
var holo = new HoloFormer(vocab: 16, shifts: 4, layers: 2, maxContext: 6, dModel: 32, frozenPrefix: 0);

var data = new List<(int[] Ctx, int Target)>
{
    (new[] { 1, 2, 3 }, 4),
    (new[] { 2, 3, 4 }, 5),
};
double loss = holo.TrainEpoch(data, batchSize: 2, lr: 5e-2, shuffleSeed: 1);

// Serve with the incremental cache: one running holographic memory per layer, so each token costs the same
// however long the context has become.
var cache = holo.NewCache();
double[] afterPrompt = holo.Prime(cache, new[] { 1, 2, 3 });
double[] afterNext = holo.Step(cache, 4);

// Read the model's mind: the resonance of the final query against every earlier position, and what it retrieved.
var alpha = new double[holo.Layers]; Array.Fill(alpha, 1.0);
int[] toks = { 1, 2, 3 };
double[][] resonance = holo.InspectAttention(toks, K: 2, alpha);
double[] retrieved = holo.InspectRetrieval(toks, K: 2, alpha);
double[] decoded = holo.DecodeFace(retrieved);          // per-token logits for what the query pulled out

Console.WriteLine($"loss={loss:F3} cache length={cache.Length} logits lengths {afterPrompt.Length},{afterNext.Length}");
Console.WriteLine($"resonance rows={resonance.Length}, positions per row={resonance[0].Length}, decoded logits={decoded.Length}");
Output
loss=2.777 cache length=4 logits lengths 16,16
resonance rows=4, positions per row=3, decoded logits=16

The pond: sources and listeners

AlgFormer is a .NET library for defining, training and running transformer-style language models, built on the Phasor codec. The atom field is the part that couples models. Several small HoloFormers, with no shared weights, write into one bundle of damped oscillators and listen to each other's notes. The answer you serve is the average of their logits, and you can train on that combined answer. The library also holds the two single-model cores, a softmax core and a holographic core, with a subword tokenizer, a data-parallel trainer, streaming generation with a cache and checkpoints. Everything is plain double arrays with SIMD. No GPU, Python or native runtime is needed, and an optional GPU package runs the same models on a GPU.

Think of a pond with sources and listeners. Each atom is a small HoloFormer. At every position it writes its state into one shared bundle of damped oscillators, like dropping a pebble of its own size and phase into the water. Each atom then listens to the pond with its own note removed, so it hears only the others.

Time lives in the medium itself. Each oscillator advances in phase and decays a little at every step, so recent writes ring loud and old writes fade, and fast bells and slow bells keep different spans of history. Space lives in the medium as well. With holographic locality, every atom has a trainable position and every channel a trainable wavevector. A writer binds a phase set by where it sits, and a reader unwinds the phase set by where it sits, so near atoms add up together and far atoms drift out of step.

In the golden configuration the atoms start on a golden-ratio spiral with golden-angle write phases, so none sits in a privileged place, and the timescales are rotated around the golden ratio from atom to atom, so every atom owns the same mix of fast and slow bells. With holographic locality, or with no locality, the cost grows linearly with the number of atoms and with the length of the text. Dense locality, the default mode when locality is switched on, costs the square of the number of atoms.

  • Holographic bundle attention, no softmax

    A standard transformer scores every token against every other token with softmax, which is quadratic in the length. HoloFormer binds each key to its value, folds them into one running bundle and unbinds with the query. Reading a prompt grows in step with its length, and serving each further token through Prime and Step costs the same however long the context is.

  • Weight-tied depth

    One layer's weights are reused for several passes, so depth is a count you choose rather than a parameter bill. The atom field runs the same K passes for every layer of every atom.

  • A population coupled by a medium

    Standard ensembles average finished answers. Here the atoms exchange information while they compute, through one shared bundle of damped oscillators. With holographic locality or none, the cost grows linearly with their number.

  • Trainable geometry

    Atom positions, wavevectors, decay times and write phases are learned parameters with exact gradients. Every dense map is a relation bank, so a layer carries S times d parameters rather than d squared.

Everything in the package

  • Two comparable single-model cores

    AlgFormer (softmax) and HoloFormer (holographic) share a model shape, a training loop, a checkpoint format and a serving API. The atom field builds a population out of HoloFormer models.

  • AtomField

    Opt-in, Memory coupling: N HoloFormers with no shared weights coupled through one damped-oscillator bundle, each reading the others with its own note removed, serving the mean of the atoms' logits. Training can use per-atom loss or the combined loss (CombinedLoss) on the mean of the logits. Weight-tied passes (Iters) per layer.

  • Locality

    Trainable atom positions and per-channel wavevectors (MemoryLocality, holographic and dense modes; holographic is linear in the number of atoms, dense is quadratic), with a golden-spiral start (SpiralPositions).

  • Diversity options

    All off by default: golden rotation of timescales (MemoryTauRotation, GoldenTauRotations), a fast-to-slow scale ladder (MemoryTauScale) and golden-angle write phases (MemoryWritePhaseDeg).

  • Molecules

    MemoryMoleculeSize groups atoms so each hears its group in one amplitude and the rest in another. It runs on the CPU only.

  • Trajectory accessor and checkpoints

    TrajectoryAllPositions for viewers, and checkpoints for the whole field (SerializeMemory, LoadMemory).

  • Data-parallel training

    Through an EvalApp pipeline (PrismTrainer).

  • Streaming inference

    Prime and Step with an incremental cache, constant work per token for HoloFormer.

  • Growth and sizing

    In-place model growth, a capacity-law sizing module (HoloShape, including HoloShape.Derive), a built-in subword tokenizer and data-source adapters.

  • Preference training

    Preference (DPO) training on the CPU HoloFormer.

  • ADAM and EVE

    An opt-in per-layer Adam gate for HoloFormer, default off.

  • Gradient-check oracles

    Built-in checks let you verify the training maths instead of assuming it is right.

  • Interpretability hooks

    AlgFormer.AttentionWeights and HoloFormer.InspectAttention.

  • Relay components

    MQTT relay components (MqttRelay, MqttJobRelay, JobSource and a peer gossip component) can move batches, or position manifests with no data, between machines. They are separate from the atom field, which has no relay.

AlgFormer.Gpu: the same models on a GPU

Optional GPU acceleration for HoloFormer and the atom field
  • EvaluatedApplications.AlgFormer.Gpu
  • Release 1.16.0

AlgFormer.Gpu adds ILGPU and CUDA backed training and inference for HoloFormer. It builds device kernels straight from a CPU HoloFormer's serialized weights, so there is no separate model format and no retraining to switch devices.

For the atom field it stacks the atoms as a batch dimension, so every layer, pass, head, reverse and Adam kernel runs once for all atoms. The number of kernel launches per step does not depend on the number of atoms.

  • A drop-in, not a rewrite

    Point it at an existing CPU HoloFormer. It trains and serves against the same serialized weights, and the CPU model stays the source of truth.

  • One build for both machines

    Device detection runs once per process. On a machine without a CUDA GPU the same kernels run on ILGPU's CPU backend, slower but identical in behaviour.

  • Checked against the CPU engine

    Every kernel is gradient-checked against the CPU HoloFormer, which computes in double precision. GPU results run in single precision for speed, so they are close to the CPU reference rather than bit-identical.

  • Adam on the device

    The optimiser step runs next to the forward and backward kernels, which avoids a round trip to the CPU on every batch.

A small HoloFormer wrapped by the GPU trainer. This run fell back to the CPU backend; with a CUDA device the first line names it.

C#
using PrismFormer;
using PrismFormer.Gpu;

// Device auto-detect: a real CUDA GPU if present, otherwise ILGPU's own CPU backend running the SAME kernels.
Console.WriteLine(GpuDevice.Describe);   // "GPU: <name> (<MB> MB)" or "CPU (no CUDA GPU)"

// A small CPU HoloFormer. The GPU trainer wraps it, and the CPU copy stays the source of truth.
var model = new HoloFormer(vocab: 16, shifts: 4, layers: 2, maxContext: 6, dModel: 8);

using var trainer = new GpuHoloTrainer(model);

var batch = new (int[] Ctx, int Target)[]
{
    (new[] { 1, 2, 3 }, 4),
    (new[] { 5, 4, 3 }, 2),
};
double loss = trainer.TrainBatch(batch, lr: 5e-2);   // forward and backward on the device, one Adam step, updates `model` in place

trainer.SyncToGpu();                                  // the device is one step behind the updated CPU model: push it across
float[] logits = trainer.Logits(new[] { 1, 2, 3 });   // inference on the device
Console.WriteLine($"loss={loss:F3} logits.Length={logits.Length}");
Output
CPU (no CUDA GPU)
loss=2.783 logits.Length=16

Good to know

  • Using the GPU path needs an ILGPU-supported CUDA device at run time. Without one, the same build still works on ILGPU's CPU backend.
  • The package is optional and needs EvaluatedApplications.AlgFormer alongside it. The core package has no GPU dependency and stays safe to trim and to compile ahead of time.
  • The device is one process-wide resource. Build, train and infer serially rather than from several threads at once.
  • In fused-Adam mode the GPU holds the live parameters and the CPU model lags. Call SyncToCpu before saving or serving the CPU model.

Know before you start

What AlgFormer does not do, and where to be careful
  • Held-out text: the eight-atom checkpoint is scored on 40 books outside its training lists. The harness results are scored on 300 held-out windows of their own book text. The six-atom checkpoints are scored on windows of their training text.
  • Generated text: greedy decoding from the eight-atom checkpoint loops and drifts, on training prompts and on held-out prompts alike.
  • Default: the atom field is opt-in in the library and the studio. A plain HoloFormer is what you get by default.
  • Scale: the harness results are small models on one text, two seeds.
  • Diversity: the diversity options (golden rotation of timescales, golden-angle write phases) are off by default. In the width-64 four-atom test, rotation raised how much the atoms depend on each other (leave-one-out cost 0.16 to 0.21) without lowering their correlation or improving the score. The eight-atom checkpoint was trained with them, and no eight-atom run without them exists.
  • Cost: linear in the number of atoms with holographic locality or no locality. Dense locality is quadratic in the number of atoms.
  • Molecules: MemoryMoleculeSize runs on the CPU only. The GPU package ignores it.
  • Holographic capacity: a holographic bundle holds a limited number of items cleanly, and HoloShape reports how many for a shape.
