Pleroma costs and checks

A superposed kernel applies in 0.17 to 0.44 ms on a 10,464-cell store whether it holds 1 or 10,368 elements, and the repair and corruption checks recovered or detected every case tried.

Headline

one kernel pass on a 10,464-cell store, from 1 to 10,368 elements
0.17 to 0.44 ms
lost harmonics rebuilt for each of 1 to 5 with 5 reserved keys
300 of 300
single corrupted cells detected in either copy
10,000 of 10,000

Where it is slower

Every loss in this record, stated once

This record measures one implementation, so no other engine is faster in it.

How it was measured

Stated once, for every figure on this page
Workload
Each row is one operation on one store shape, timed or checked on the shape named in the row. Checks are exhaustive or random within the stated count.
Engines
Pleroma, release build
Check
Every timed operation is compared with a brute-force or naive implementation, and each check counts the cases that matched.
Statistic
Per-call times, warmed up, with the range across repeated runs where one is shown.
Machine
One laptop CPU (Intel i9-11950H), release build, with other work running.
Memory and logging
Page and kernel figures use the default field.

Limits

  • Times are warm, single-call figures on one machine. Cold-start costs, including compilation, are larger.
  • Every row is the Pleroma alone, without a database or a model around it.
