Exact recall and refusal

At equal storage the exact key view recovered 64 items with no errors where holographic reduced representations held 95 percent or better only up to 4. Past capacity the exact store refused every time, while the baseline answered wrongly every time.

Where it is slower

Every loss in this record, stated once
  • At 64 pairs the exact store is past its capacity and refuses every query, so it recalls none, while the float bundle still recalls 9.5 percent of values, though it never says when it is wrong.
  • Exact arithmetic is not faster in general. A Pleroma read costs one or more transforms, while a float bundle read is one correlation. At equal bits float reads are often faster.

How it was measured

Stated once, for every figure on this page
Workload
Two measurements of a keys-only store, the Pleroma's single-face special case. Exact recovery: store k distinct symbols from vocabularies of 4,096 and 2^20 symbols and read them back, at capacities from 1 to 96. Associative recall: store n key and value pairs from a codebook of 256 values and recall each value from its key.
Engines
Pleroma keys-only store (CycleHologram); Plate's holographic reduced representations with correlation clean-up; The same representations with a stronger peeling decoder (orthogonal matching pursuit); A float bundle of complex phasors, at full and half the bits (recall table)
Check
Every exact decode is re-encoded and must reproduce every stored element before it is returned.
Statistic
200 trials per capacity point. Associative recall uses 20 random seeds, with a chance level of 0.39 percent.
Machine
CPU only, one core.
Memory and logging
Stores are compared at equal storage: about 2,064 and 2,580 bits for exact recovery, and 3,965 bits for the exact arm against 3,904 bits for the float arm in the recall table. The 7,869-bit budget was not measured.
Ties
The exact read in the recall table is decode then test, not a ShiftKeys read. It measures recall, not model quality: a trained model can learn around float noise.
