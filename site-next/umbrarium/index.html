Umbrarium: 100,000,000 rows, exact, in one browser tab.

Press Build. The real dashboard engine generates the rows in your tab and answers every chart exactly: 2,000,000 rows in 4.2 seconds, 100,000,000 in 3.6 minutes, then every click slices every chart. The whole stack runs in your tab, on one thread. Scale it up with the size chips.

What you are looking at
  • The rows are generated in this tab when you press Build. They are demo data, not anyone's records, and they do not change while the page is open.
  • The engine is the same code Umbrarium runs as a service, compiled to run in the browser. The dashboard on screen is the real one, not a mock-up.
  • Every answer is exact, not sampled. A panel tagged "exact summary" was answered from a summary kept next to the rows, so the click did not rescan them. A panel tagged "row scan" was answered by scanning the rows in this tab (a row list, or a column that is not a slicing dimension).
  • "Rows behind this view" shows the rows that make up the current slice.
  • The whole stack is running in your browser: the database engine, the exact-summary layer, the pipeline runtime and the dashboard. A browser tab runs it on one thread, because WebAssembly here is single-threaded. The same code on a server uses every core, so what you see here is the floor, not the ceiling. Scale it up with the size chips, from 100k to 100M rows.
  • The live feed is simulated. Inserts, updates and deletes arrive at the rate you choose in the configuration panel, produced by the demo itself. No database is connected.
  • Nothing leaves this tab, and the generated rows and the answers are gone once you close it. The first visit downloads the .NET runtime that does the computing; your browser keeps that, and a one-word note that you have opened the demo before, for next time.
Measured: how big it goes

A single headless Edge run on one development laptop (i9-11950H, 16 cores, Windows, the AOT build), with generated rows. The footer of the demo shows your own timings.

The rows are generated in your tab by a pure function. The exact summary keeps exact counts and sums for every slice, not the rows, which is why memory stays flat at 115 MiB from 5,000,000 rows to 100,000,000. At 100,000,000 rows a brush on a chart is answered in a median 148 ms.

What a live Umbrarium adds

Umbrarium is built for SQL Server. A live Umbrarium keeps a replica of your SQL Server database and the dashboard exact over it, and it keeps that replica fresh as the database changes. The capture modes are rowversion, Change Tracking and an updated-at column. The dashboard then states how current its numbers are. This demo has none of that: it has no database behind it and no capture, only the engine, the generated rows and a simulated feed.
