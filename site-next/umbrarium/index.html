Umbrarium, preset demo

The real dashboard, running in your tab.

The demo

Open the demo on its own page

About the demo

Pick a table size, press Build, and the real Umbrarium dashboard engine builds its data in your browser tab and answers over it: up to a million generated rows, every chart exact, every click slicing all the other charts at once. No server is doing the work. Each panel tells you how it was answered and how long it took, and the footer shows how long your own machine took to build the data.

What you are looking at
  • The rows are generated in this tab when you press Build. They are demo data, not anyone's records, and they do not change while the page is open.
  • The engine is the same code Umbrarium runs as a service, compiled to run in the browser. The dashboard on screen is the real one, not a mock-up.
  • Every answer is exact, not sampled. A panel tagged "exact summary" was answered from a summary kept next to the rows, so the click did not rescan them. A panel tagged "row scan" was answered by scanning the rows in this tab (a row list, or a column that is not a slicing dimension).
  • "Rows behind this view" shows the rows that make up the current slice.
  • Nothing leaves this tab, and the generated rows and the answers are gone once you close it. The first visit downloads the .NET runtime that does the computing; your browser keeps that, and a one-word note that you have opened the demo before, for next time.
  • A larger table needs more memory and a longer wait. Sizes above 500,000 rows keep only the columns the charts use.

Reference run, for context only: on one development machine, one headless Edge run built 1,000,000 rows in 2.0 s, showed the first panel after 3.3 s, answered a chart click in a median 44 ms and used 344 MiB. Your numbers depend on your device and browser.

What a live Umbrarium adds

Umbrarium is built for SQL Server. A live Umbrarium keeps a replica of your SQL Server database and the dashboard exact over it, and it keeps that replica fresh as the database changes. The capture modes built today are rowversion, Change Tracking and an updated-at column. The dashboard then states how current its numbers are. This demo has none of that: it has no database behind it and no capture, only the engine and the generated rows.
