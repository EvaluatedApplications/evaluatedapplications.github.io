Three million rows. One browser tab. Press Build.

This is the real Umbrarium app, not a cut-down copy. Pick 100,000 to 3 million generated rows and press Build: the data engine, the dashboard and the SQL console all run inside your tab, on one thread.

What you can do, and what you are looking at

Pick 100,000, 500,000, 1 million, 2 million or 3 million generated rows and press Build. At 3 million rows the build takes 6.3 seconds on a fast laptop, and a chart click then redraws every panel in about a tenth of a second. A server install of Umbrarium uses every core; your tab uses one. Each panel tells you how it was answered and how long that took, and the footer shows how long your own machine took to build the data.

  • Click any bar and every other chart slices to match. Every number is exact, not sampled.
  • Write SQL. A full SQL console runs on the same data. It reads only: anything that would change the demo tables is refused. You can make scratch tables of your own and fill them. The built-in examples include a join and a nearest-name search.
  • Watch a live feed. A simulated feed adds, changes and removes rows while you look. It is labelled simulated wherever it appears; the rows are generated, not anyone's records.
  • Take the guided tour. It starts the first time you open the demo and takes seven short steps. Press Esc to skip.
  • The rows are generated in this tab when you press Build. They are demo data, not anyone's records.
  • The engine is the same code Umbrarium runs as a service, compiled to run in the browser. The dashboard on screen is the real one, not a mock-up.
  • A panel tagged "exact summary" was answered from a summary the engine keeps next to the rows, so your click did not rescan them. A panel tagged "row scan" was answered by reading the rows in this tab (for example the list of largest orders). "Rows behind this view" shows the rows that make up the current slice.
  • Nothing leaves this tab, and the generated rows, your scratch tables and your answers are gone once you close it. The first visit downloads the .NET runtime that does the computing; your browser keeps that, plus a one-word note that you have opened the demo before, for next time.
  • A larger table needs more memory and a longer wait. See the measured numbers.
Measured in a browser tab

One run of this page on a fast laptop (Intel Core i9-11950H, 32 GiB), headless Edge, one browser thread, and nothing else running. Slower devices take longer. The 3 million row size needs about 1.6 GiB of free memory: peak 1,564 MiB measured.

What a live Umbrarium adds

Umbrarium is built for SQL Server. A live Umbrarium keeps a copy of your SQL Server database and the dashboard exact over it, and it keeps that copy fresh as the database changes. The capture modes are rowversion, Change Tracking and an updated-at column. The dashboard then states how current its numbers are. This demo has none of that: it has no database behind it and no capture, only the engine and the generated rows.
