# Site rework proposal (INTERNAL)

Internal planning document. Not rendered, not in `site-next/`, not in `web/data/`. Nothing here goes into a public page as written: the pages say only what is measured and published.

Scope: HoloDb 9.0 (learns from its workload, keeps only what pays) and the atom field (a population of small HoloFormers coupled through one shared wave medium). The page words come from `HoloDb/docs/site.md` and `AlgFormer/docs/site.md`. This document is design, structure, data plumbing and order.

Rules that bind every lane: no roadmap or "soon" text in pages; no versions in prose; the licence is commercial (never "free to use", "MIT", "open source"); the founder's inventions are stated without hedging; every number measured and sourced; a limit is stated once, in a status table; no outreach copy.

## 1. The new story

### 1.1 Home promise

Current: "Data that answers in microseconds. Models that run in a browser tab." (`site.json` pitch).

Proposed:

> A database that learns what you read, and a team of small models that think through one shared wave. Both are .NET libraries. Both run in your browser tab.

Short form for the hero H1: **"Software that learns from its own use."** Sub-line: one sentence per flagship. The home keeps the stack scene (`stack-map.js`) and the product gallery; the hero tool band changes from "pick a product" to the two flagship demos side by side.

Hold: the second half of the promise ("run in your browser tab") must stay true for each tile. The atom demo can only claim it once the JS toy (section 3, A1) is live; the model-backed version waits on a published AlgFormer.

## 6. Risks

- **Stale Showroom dist.** `Showroom/dist` is committed and CI never rebuilds it. It pins HoloDb 5.1.2, AlgFormer 3.3.0, Prose 1.3.2, Blazier 1.0.0, Tracer 2.0.4, HoloGenome 0.2.0. A tool band that claims a 9.0 behaviour while the tool runs 5.1.2 would be false. Until showroom-owner rebuilds with the new pins, tool bands must not describe 9.0 behaviour live, and the recorded explainers carry the claim. The Umbrarium demo has its own shell (`umbrarium-demo/`) with a runtime in `website-data`; a refresh is a separate publish.
- **Extractors read `C:\HoloDbBench`.** `extract-holodb-race.mjs` reads `n100000000\results\*.json` and `manifest.json` with arms hard-coded as the older `holodeclared-s4`, `holopaged-s2`, `duckdbtuned`, `sqlservertuned` (and repeat ids); the stored results for builds 7 and 8 use `holopaged7`, `holopaged8`, `holodeclared7`, `holodeclared8` with `-f1`/`-f2` suffixes. The extractor needs the 9 arm ids and a rule for the repeat round (`-f1`, `-f2`). Output is committed because CI cannot read the folder. The results exist only on this machine: back them up before the machine changes. A mislabelled build is the main risk: an old-build result shown as 9.0.
- **Version badges and generated stamps.** Pages show versions from `versions.json`. The committed file now says HoloDb 6.0.1, AlgFormer 3.3.0. If the pages go live with new words and old badges, a reader sees 6.0.1 beside 9.0 behaviour. `build.mjs` default mode (`auto`) reads the csproj and writes the unpublished versions; that was seen in this task. Always build with `--versions=committed` unless the version is on NuGet's flatcontainer index.
- **Diagram data stamped with old versions.** `check-site` warns on every generated diagram whose package version is behind (Phasor 2.21.1 against csproj 2.23.0, NuGet 2.22.0; EvalApp, HoloGenome, Prose, Tracer behind). Regenerate on bump (L0).
- **Owner source files with internal headers.** `HoloDb/docs/site.md` carries an INTERNAL header, a `TO MEASURE` block and a `[GATE]` marker. They must never render. The extractors must strip HTML comments and the `TO MEASURE` section, and `lint-voice` must reject `GATE`.
- **Unstable evidence sources.** The overnight ablation output lives in a coordinator scratchpad, the harness table in a `todo/` note that can be edited. Copy the result into a fixed file before an extractor reads it.
- **"Beats one big one" claim.** Strictly: six atoms with split views score 2.99 against one atom reading the whole window at 3.38, at small scale on one text with two seeds; with every atom reading the whole window the six score 2.47. The owners' status table says no held-out score exists. The tile promise must be exactly what that data supports. I suggest the promise reads "six small models that each see a sixth of the text beat one that sees all of it" and the page says no more.
- **Budget.** Several existing diagrams are near the 40,960 byte limit (`holovoxel-lod` 39,289, `tracer-field` 37,795, `coverage-meter` 35,370). New modules must share `core.js` helpers.
- **CRLF.** A CRLF working tree breaks the CI guard (`site.js` hash). Build from an LF clean clone.
- **Pre-existing browser failure.** `verify-diagram` fails "reduced motion: motion starts only when the visitor presses Play" and, in this environment, a console error from an Edge-injected `AssistantLoadState` script. Fix the first before adding more animated diagrams, so new ones are judged against a clean baseline.
